# 录音后分类与日期批次

用户已确认：四固定分类A美食/B旅行/C相遇/D其他回忆。开空卡不分类不分活动批次，参观者选分类后录音，最终成功绑定时云端原子赋类及编号。批次为绑定成功时间的Asia/Tokyo日期；每日期每分类从001计数，用过不复用，超过999自然扩展。显示例261017-A003，数据库保存完整YYYY-MM-DD日期。编号只作显示/管理检索，公开身份仍为原随机token网址。

已写NFC不改网址。历史录音/旧编号保留，不按未知主题强制重分类；新空卡无类。每张卡另有稳定内部库存号U000001，便于尚未录音的写卡/检索。重置解除当前分类/日期/序号，旧序号历史永久保留，下次重新成功提交生成新号。管理员可纠正已有录音分类，使用原录音日期的新分类下新序号，旧号不复用；不允许对空卡预分类。后台不再创建/改名分类。

API冻结见docs/API_CONTRACT.md V3。父Agent单独维护domain、repository、契约、部署；后端Agent仅supabase及合成验证脚本；网页后台Agent仅features/admin；安卓Agent仅apps/tag-writer-android。固定接口后按所有权独立实施，不得并行改共享文件。生产迁移与上线仅由父Agent操作。

V3写卡协议统一未分类池；旧协议明确升级提示。不把待录音卡的写卡日期当录音批次。后台支持日期批次/固定分类/待分类筛选，搜索新旧编号，保留批量开卡、试听、分组删除/重置等。用户完成页及后续收听页小字显示正式编号；五语流程及独立测试入口同样更新。

验收须覆盖并发同卡/不同卡分号、跨日/时区/999后、失败不绑、重置失效旧上传、授权、历史数据/URL保留、空卡批量幂等、协议保护、前端全测/两构建、Android单测构建lint和云端合成联调。实体手机NFC不以自动化结果替代。
