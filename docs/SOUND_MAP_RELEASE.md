## 当前状态

2026-10-29，本地集成位于 `codex/visitor-sound-map`。用户确认设计并要求先接入真实数据，再停在上线确认之前。没有推送、部署函数、迁移数据库、改DNS/Pages设置或写入生产录音。

本机运行：

```sh
npm run dev:sound-map
```

当前地址 `http://127.0.0.1:4180/#/map`。如果端口被占用，Vite选择其他端口，以启动输出为准。脚本需要已有Supabase CLI登录，或在当前Node进程环境提供服务端凭据；不要把服务端密钥写入 `.env`、VITE变量或网页。CLI读取项目凭据的stdout只在进程内存解析，不输出到终端。

桥接使用 `public-map/handler.ts`，仅有GET展览目录，绑定loopback，限制Host与Origin，拒绝POST；无本地管理员写接口。现有录音提交仍走生产API，浏览本地地图不代表可以提交测试录音。开发者不能以只读桥接为由放宽生产表RLS。

## 数据事实与限制

- 只读目录49条有效录音，其中42条有用户经纬度（全部在当前沙盘内，4条位于原区域西侧）；6条只有Google place ID；1条未选地点。
- 全部49条均可从声音列表收听；42条用户坐标显示在三维沙盘。6条place-only录音提供原Google Maps入口，不把受限供应商坐标放到独立地图，也不伪造点位。
- 让这6条也显示在沙盘，需要另行确认独立来源点位；目前没有自动补坐标或改写任何历史记录。依据：[Google Places政策](https://developers.google.com/maps/documentation/places/web-service/policies)。
- 沙盘本身不依赖Google服务。原录入/Google地图功能的浏览器key仅允许生产域名与本机5173端口；4180的录入地图可能受来源限制，本轮没有更改Google生产key设置，也没有在生产创建录音来验收录入。
