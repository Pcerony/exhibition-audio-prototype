# 在线声音沙盘设计

用户已在本聊天确认三维效果、研究室logo标点和分层地标标注，并授权接入真实数据到本地应用；在正式发布前停下等待确认。

## 体验

- 独立、免安装、免账号的 `#/map` 声音地图。芯片录音页的开始前、提交成功后、已有录音的收听页均提供入口；离开沙盘后保留原标签和流程状态。
- 延续确认过的低细节、真实街区轮廓三维沙盘。默认视野仍聚焦实体地图核心区域，向西延伸到大濠公园，少数外围点不挤压初始视野。
- 使用研究室伞形logo小立牌；单点直接打开紧凑播放条。屏幕距离小到无法分辨时才显示数量和选择菜单；缩放后重新判断，不固定按地理网格分组。
- 车站、主要建筑、神社、公园和道路名称按缩放显示。地名保留当地日文，操作与告知支持日、简中、繁中、英、韩；标注避让文字、logo和操作栏。道路标签转向只用于识别，不是导航路线。
- 声音列表作为辅助入口与无3D设备回退，不常驻。无地点、只有供应商place ID或超出范围的录音都能从列表收听。切换或关闭录音停止上一条，不自动播放。
- 提交成功页面不再要求插卡到实体地图；实体地图放置为可选。新提交明确告知会通过在线声音地图公开。

## 数据与安全

- 用户明确批准已有录音展示。使用新匿名只读 public-map 最小DTO，不返回草稿、路径、签名URL、人员信息或未绑定库存。RLS不改变，不迁移音频，不修改现有 token/绑定/写卡协议。
- 播放仍经过既有 public-tag/current-recording核对和 public-playback-url 120秒签名，不下载全库音频或放开存储bucket。
- Google Places 官方政策要求其地图结果显示在Google地图；独立沙盘不调用Places解析坐标。仅place ID的历史记录保留原Google Maps链接和列表收听，若需要沙盘点位，需另行确认独立坐标。不能靠把供应商坐标改标成用户pin来规避。
- 几何与地标JSON为独立静态资料，不含真实录音数据。3D只在操作时重绘，限制像素比，不做动态阴影/后处理，退出时清理GPU资源与监听。

## 本地与发布边界

本机开发入口 `npm run dev:sound-map` 只在loopback启动，复用相同目录handler读取当前云数据，凭据只在Node内存，端点无写接口、拒绝其他Origin。正式构建不包含该桥接；上线需先部署public-map，再发布前端。

当前读到49条有效录音：42条用户坐标全部位于沙盘范围，6条place-only以及1条无地点进入列表。这是实际数据状态，不是虚构演示点。服务端新函数、前端和数据资料均只改本地；推送、生产部署和生产数据写入均需下一步用户确认。
