# 二维码录音补实体卡

二维码签发已经上线。本轮补齐 Android 运营端，沿用原身份、原网址、原编号、原音频。新增“二维码补卡”列表，支持编号/库存号搜索、录音日筛选、试听和已补卡状态。尚未录音的入口展示等待，不允许补卡；完成录音后显式选择记录并确认写卡。

采用独立私有 `qr_card_attachments`，不把二维码任务放回普通 provisioning 池。每 tag 最多一条任务，绑定原 recording ID 和 tag version；重置、删除、禁用或录音改变时拒绝旧操作。只允许 operator/admin，不扩展共享 staff 审核账号权限。旧 APK 继续可用。

准备任务、首次触卡登记、写后读回、结果上报分开处理。首次触卡先读取，只有空卡/可格式化标签，或同网址的重试卡可以继续；其他数据拒绝覆盖。客户端把 UID 的 SHA256 作为运营去重键（不是公开身份），首次登记后任务只允许同一芯片重试；不同记录不能登记同一 hash。没有 UID 时失败关闭。不能防止克隆芯片或第三方复制公开网址。

标签行锁和唯一约束防止多人重复分配；10分钟租约绑定账号/设备。过期后只手动恢复同一任务、同一芯片。每次物理写前验证原录音、版本、租约和 UID hash，写后重连读回完整网址，报告持久化并按原租约重放。网络不确定时不得换芯片。verified 任务不可开始新写入，原报告可幂等重试。

发布顺序：备份与迁移回滚预演 → 迁移/Edge → 云端合成校验 → APK → 更新清单。JVM/PG 并发测试不替代实体 NFC；保留其他工作区修改。
