# 管理手机应用V3：安装与验收

## 3.4.0二维码录音补实体卡

1. 在工作人员网站 `https://voice.heisei.space/#/staff/qr` 为参观者生成二维码。对方扫码，按原流程录音；没有实体 NFC 也能参与。
2. 录音提交后，打开安卓应用“二维码补卡”（日语“QR補充”）。用编号/库存号搜索，或按录音日期查找；先试听核对。未完成录音的记录没有写卡按钮。
3. 点“将此录音写入空白芯片”，确认编号，然后触碰一枚空白芯片。应用先读取内容，仅允许空白或同网址重试，其他内容不会被覆盖。
4. 等待写入、重新读回和云端确认。成功振动后移开芯片，记录显示“已补实体卡”。同一条记录不会再新配第二张卡。

这是把原网址写到实体芯片，不会新建录音、换编号或改变原二维码。下一位参与者必须生成另一个二维码，不要复用已发出的入口。

重试只使用第一次登记的同一枚芯片；无 UID、只读、容量不足或内容不符都会停止。芯片已写好但断网时不要换卡，保留待同步结果，联网后自动同步；即使十分钟后才收到原结果也支持安全补报。跨设备晚到的成功结果会清理已被取代的旧失败报告。系统不能阻止第三方复制网址或克隆芯片。

已有3.3.0可在设置“检查更新”升级到3.4.0；更早版本需要手动覆盖安装一次，**不要卸载旧版**。使用原运营者账号登录，网页共享 staff 账号不自动获得写卡权限。更新与安装说明见 [应用内更新](ANDROID_UPDATES_ZH.md)。

自动化不能代替实体卡验收：请用一条测试二维码录音，补写空卡、触卡播放，并测试断网重试同卡、碰到另一枚卡被拒绝、已有内容不被覆盖。请勿用真实参观者卡做破坏性测试。

## 3.2.0单张先读卡再操作

进入“单张写卡”后，先触碰实际芯片，不再先从云端任务列表选卡。页面展示空白/已有NDEF、是否为展览网址、原卡号及录音状态；原录音可试听。展览卡云端查询失败时标为无法确认，不能当作没有录音，也不开放破坏性操作。

读取后可选择：
- 清空芯片内容：移除芯片可读的NDEF网址/文本并读回核验，不删除云端卡片、录音或改云端写卡历史；不是芯片全存储区的安全擦除。
- 写入新的展览网址：创建独立新卡和新网址，原录音不删除，但这枚实体芯片不再指向旧录音。新卡创建幂等，准备失败不反复生成网址。
- 写回原展览网址：仅对已确认的唯一有效原卡提供，保持原云端卡片与录音，不换成其他卡。

清空/覆盖需明确确认，随后再次触碰同一枚芯片。应用核对临时芯片标识和完整NDEF指纹；换芯片、内容变化、录音状态变化、切后台或等待过期均拒绝原授权。只读/锁定和容量不足不可绕过。

写入后断连/读回失败可能已改变芯片，因此不会把同一待定网址自动写到另一枚芯片。先重新读卡核对；需要放弃待定准备时，使用单张页面的核查入口明确丢弃本机准备记录，新的写入会创建另一网址，不删除原云端内容。连续写卡与独立只读入口保留。

## 3.1.2连续写卡与成功振动修复

修正云端确认完成前芯片已经移开时被错误暂停的问题：成功反馈至少停留1秒后自动准备下一张，不再要求每张暂停/开始；仍在场则等待移开。成功改用事件型短双振，失败节奏不同，静音/勿扰和设备振动设置仍有效；提示音开关独立。

芯片已有未录音网址也不是空芯片。普通/连续模式拒绝覆盖不同网址，已有录音同样保护；只有单张明确确认覆盖才替换网址，不自动删除原云端录音。先“读取 NFC”核查，详细对照见 [芯片已有内容与现场对策](ANDROID_CARD_SAFETY_ZH.md)。

## 3.1.1工作人员界面简化

工作人员不再手动分类：网页与安卓移除分类侧栏、分类筛选、未分类入口及移动分类。用录音日期区分当天活动，配合搜索、录音状态和排序管理；保留试听、转写审核（网页）、重置/删除与写卡。

参观者四主题不变：A美食、B旅行、C相遇、D其他回忆。空卡初始一样，只有参观者提交录音后才自动体现在编号上，不需要工作人员提前设置。旧数据、网址和编号不变，详情和导出可被动保留主题信息。

旧安卓若保存了尚未确认结果的移动分类操作，新版不会继续发送。先核查旧操作是否已在云端完成，再明确丢弃本机旧请求；不自动清除不确定请求，也不把它重新当作可执行分类功能。

## 3.1按需写卡

不必先在网页后台开空卡。进入“连续写新卡”，点击开始，应用会自动准备一个独立网址；先复用可用待写任务，没有才在后台创建。分类仍由参观者录音时选择。网页后台保留批量创建备用，主要用于查询、试听、转写审核、重置和批量管理。

写卡过程中有应用内大弹窗：准备中不可触碰；“请触碰芯片”后贴近；写入与读回时保持贴近；看到成功并移开后才准备下一张。成功/失败有不同反馈；设置中可以关闭提示音，静音与震动遵循系统设置。无需悬浮窗权限。

如果显示“芯片已写入，等待同步”，不要把同一网址写到另一枚芯片。恢复网络让原结果同步，过期冲突时先用读取NFC核对再处理。物理写卡失败停在当前任务，重试不会重新创建网址；中断写入可能已经改动芯片，停止不等于撤销。后台预留但未成功写出的记录仍标为待写，不能当成实体卡数量。

新增实体验收：同一芯片一直贴着不连续处理；移开并等待成功反馈结束才开始下一张；准备阶段网络断开重试不增加空卡；在不同阶段切后台/返回/退出登录后不继续写入或弹窗；静音和声音开关、成功/失败震动、屏幕小字号可读性；写后读回成功但云端断网时明确待同步而非失败重写。

## 本次升级

Android工作人员应用本轮升级为3.1.1，保留无需网页提前开卡的连续写新卡。参观者录音提交成功后自动确定A美食/B旅行/C相遇/D其他回忆，并按日本录音日期生成261017-A003这样的序列号，不再提供工作人员分类操作。空卡用U开头的库存号识别；已有NFC网址不变。仍提供中/日/英三语、记住登录、列表试听、单张/独立连续写卡和批量重置/删除。

2.1试用版新增独立“读取 NFC”入口：先查看芯片内容，再联网确认展览分类、编号和录音并试听。此入口只读，不写卡、不格式化、不锁卡。

2.1.1修复“重新写卡”不能替换其他已有内容：进入单张写卡，选目标卡片，选择“覆盖已有内容”，核对目标编号并确认，再触碰要覆盖的芯片。许可仅用于这一次触碰；失败、切后台或切换页面后需重新确认。不先清空芯片，直接用完整目标URL替换NDEF并读回核验。只读/锁定芯片不能强制写入，原云端录音不会自动删除。自动模式仍拒绝覆盖其他内容。

APK是调试签名试用包，不是应用商店正式发行。只支持Android工作人员手机；参观者仍用iPhone/Android浏览器，无需安装。

## 安装前

1. 结束旧版写卡，确认没有待同步结果。本次负责人已确认可以统一升级。
2. 下载本次发布的 `voice-writer-v3.2.0-candidate.apk`，在Android允许所用浏览器安装此来源的应用，然后安装。
3. 优先覆盖安装，保留同一签名包的数据。如果系统提示签名冲突，不强行覆盖；先再次确认旧版没有待同步结果，再卸载旧版并安装新版。云端卡片和录音不因卸载而删除。
4. 用已有运营账号登录，不要用Google/Supabase控制台账号代替展览运营账号。首次登录后，应用在设备安全存储中保存加密续期会话，不保存明文密码。

## 五个入口

- 卡片管理：按录音日期、搜索、状态和排序查找，查看录音与写卡状态、提交时间，试听。
- 读取 NFC：无需选择分类，碰一下芯片。显示空卡、未格式化、网址/文本/其他记录或读取失败；有效展览链接联网确认后显示编号、当前分类及录音。点击“重新读取”再碰下一张；云端查询慢时仍可切换页面或重读。断网不丢失已读内容，可重试云端查询。此模式需要先登录；不承诺首次登录或冷启动恢复会话可以离线完成。
- 单张写卡：先读实体芯片，确认已有内容及原录音后选择清空/新网址/写回原网址；确认后再触碰同一枚芯片执行。不同芯片或内容变化会停止操作。
- 连续写新卡：直接开始，不选分类、不填数量。自动准备当前设备的唯一网址，可用池无任务时自动创建；每张成功后移开芯片，等反馈后换下一张。普通卡片列表不会自动写入。
- 批量编辑：选择卡片后重置或删除，不再提供移动分类。删除按空卡与已有录音分开确认；重置保留网址、清除录音主题和正式序号，恢复库存号。

日期筛选表示用户录音提交的日本日期，不是创建网址或物理写卡日期。旧版待同步结果保留原协议，不能伪装V3自动上报；请明确核对或丢弃后重新核验，不能直接视为已写卡。

顶部设置提供语言、账号/退出登录和NFC设置。失败或断网时看当前提示，不要把未同步项当成云端已完成；不能用跳过冒充写入成功。

## 必须用实体手机确认

1. 登录后关闭并重新打开应用，确认恢复会话；切换三种语言，检查主要页面和错误提示。
2. 不在网页预开卡，直接开始连续写新卡，用至少两枚测试芯片，再用另一手机碰它们，确认各自完整网址与后台任务一致、互不相同；另测手动预开与单张写入。
3. 录一段测试音频，再用另一手机打开并播放，后台也应能试听。
4. 自动模式下保持同一枚芯片不移开，确认不会自动覆盖为下一编号；移开后换另一枚再继续。
5. 检查NFC关闭、断网、切后台、只读/容量不足标签的提示和暂停行为。没有这些标签时标记未测，不猜测通过。
6. 在“读取 NFC”分别读取空芯片、本展览芯片和其他网址/文本芯片；核对分类、编号与试听，确认芯片内容前后不变。断网读取、移开过快和切后台后重试也需验证。
7. 单张先读空卡/外部网址/已录音卡，核对显示后分别测试清空、新网址、写回原网址；确认后换另一枚芯片必须拒绝，确认后修改原内容也必须拒绝。清空读回后原云端录音仍存在。连续模式仍拒绝其他内容。切后台后原授权失效；写入中断先读卡，不保证原内容完整。
