# 芯片已有内容时会发生什么

芯片只存网址；空网址不是“空芯片”。有网址但未录音，仍是一张已经写过内容的卡。录音状态在云端，不能仅靠芯片字节判断。

| 芯片现有内容 | 普通单张 / 连续写新卡 | 明确确认“覆盖已有内容” |
| --- | --- | --- |
| 没有NDEF内容 | 写入当前任务网址并读回 | 同左 |
| 有未录音的展览网址，与当前任务不同 | 拒绝，不替换网址 | 替换为当前目标网址，原卡记录仍在云端 |
| 有已录音的展览网址，与当前任务不同 | 同样拒绝，不改旧录音 | 替换网址，原录音仍存在，但这枚实体芯片不再指向原录音 |
| 与当前任务是完全相同的唯一网址 | 可以重复写入并核验，不会重置音频 | 同样不重置音频 |
| 外部网址、文本或多条其他记录 | 拒绝，不替换 | 替换完整NDEF，原芯片内容丢失 |
| 已锁定/只读、容量不足或不支持 | 明确报错 | 也不能绕过硬件限制 |

普通/连续模式的拒绝发生在NDEF写入前；会留下本次失败的任务记录，不代表芯片被清空。若存在设备断连、写入中断等其他故障，芯片内容可能已部分改变，需先读取核查。

## 现场推荐

1. 不确定旧卡时先进入“读取 NFC”，核对原卡号、是否已有录音及实际网址；网络失败显示无法确认时不要当作未录音。
2. 连续写新卡只用空芯片。意外碰到已写卡会停在当前任务并提示核查，不自动强行覆盖，也不会给已录音卡换成新网址。
3. 需要修复原芯片时，在单张模式选择读取结果对应的原卡片，写回相同网址。不要误选一张新的空卡记录，否则原录音虽未删除，但芯片会指向新卡。
4. 确实要改用途才使用“覆盖已有内容”。覆盖只授权当前任务的一次触碰；失败、换页面或切后台后重新确认。
5. 想让原卡重新接受录音，应在管理端明确执行“重置录音”，不是覆盖芯片。重置是会影响云端录音的独立操作，不应当作写卡故障的默认修复。

不同实体芯片如果写了同一个网址，会共享同一条云端卡片/录音，系统无法凭相同网址区分它们。不要通过手动重复写同一个目标网址来批量制作“独立卡片”。

## 连续写卡验收

用两枚可丢弃的测试芯片：第一枚写入成功后移开，不点暂停或开始，等应用自动显示下一张的“请触碰芯片”，再写第二枚。两枚网址应不同。第一枚一直贴住时不应覆盖为下一任务。

3.1.2新增成功事件短双振，失败为另一节奏；系统静音、勿扰、无振动器或厂商限制可能抑制振动，不强行绕过。提示音仍可单独关闭。成功反馈包含云端确认；若显示“已写入等待同步”，勿用同一个任务网址改写另一枚实体芯片。
