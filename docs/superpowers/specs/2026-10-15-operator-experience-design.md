# 分类管理与工作人员应用体验设计

日期：2026-10-15。状态：用户已确认交互方向，本文固化设计供实施前复核；功能尚未实现。替代体验阶段简报中“仅优化写卡、不扩展手机管理”的早期范围假设。

确认边界：分类单选、自动编号、跨分类换号且旧号不复用、批量删除分开确认、三语、记住登录、分页面管理与独立自动写卡模式来自用户确认。分类代码超过Z的规则、单次500张上限、逻辑删除、旧数据映射、任务租约和过时客户端限制是本稿补充的工程建议，随本文一并待复核，不冒充用户已逐项确认。

## 1. 本轮范围

网页运营后台与工作人员 Android 应用一起更新，围绕分类、自动编号、批量开空卡和管理、清晰的单张/自动写卡工作流。Android 增加卡片浏览、试听与批量管理，不建立另一套数据库。参观者网页视觉改版不在本轮范围；唯一网址、匿名参与、私有音频、服务端权限与原子绑定保持不变。

## 2. 术语与身份

- 分类：管理员创建的单选归属，如食品、景点、其他；不再以自由文本“批次”代替正式分类。
- 卡片/展签：稳定内部 ID 和随机 token 对应的记录，可关联一枚物理芯片和最多一段有效录音。
- 展示编号：分类代码加序号，如 A001；是管理标识，不是公开访问凭证。
- 芯片写卡：工作人员写入 URL 并物理读回，不等于参观者提交音频。
- 录音提交：参观者上传并由服务端绑定成功，以该时间为录音时间排序依据。

分类代码按创建顺序自动分配 A–Z、AA、AB…，不复用已分配代码；名称可以修改，代码不随名称变化。每张卡仅属于一个分类。序号至少三位，超过999自然扩展为1000，不截断或循环。

## 3. 编号、批量创建与移动

管理员选择分类并输入数量，一次生成空卡、编号、独立网址和待写任务；单张创建使用同一路径、数量为1，不再要求人工输入序号。初版每次1–500张，与当前批量接口上限一致。

每个分类有服务端持久递增计数器；分配、建卡和幂等响应在同一事务完成。并发创建不重号，相同请求重试不再次分配。删除、重置不回收旧号；编号允许有空缺，不保证绝对连续。

允许跨分类移动：A003移入B时取得B的下一个编号，如B012；A003永久空置。内部ID、token、完整URL、录音、物理写卡状态不变，不要求重写NFC。再次移动也分配新号。移入本分类为无操作，不消耗编号。移动写审计并在网页及安卓刷新后显示新编号。

移动预览显示数量、来源和目标分类，告知编号变化但芯片网址不变。已有录音也可移动，不覆盖音频。记录版本用于阻止过时界面的批量变更；并发冲突返回可刷新重试的明确错误，不悄悄覆盖。

## 4. 网页后台

分类导航与卡片列表分层；分类可以创建和改名。本轮不提供删除分类或任意修改分类代码，避免误伤归属与编号历史。

列表显示编号、分类、录音状态、芯片写卡状态、昵称、录音提交时间及操作。录音状态与写卡状态独立展示；未录音时间显示空值。支持分类筛选、编号/昵称搜索、状态筛选、录音时间升降序，默认最新录音在前、空卡在后，稳定ID作为同时间排序次键。

可直接试听、单张重置/停用、批量选择后移动/删除/重置。批量修改本轮明确指分类移动与重置，不开放修改参观者昵称、音频或任意编辑编号。选择默认限当前页，切换分类/搜索/筛选清空选择；不做隐式跨页全选。

## 5. 删除与重置

删除和重置是不同命令：重置保留卡片ID、编号、URL及芯片写卡状态，解除录音并使旧上传失效；删除使原URL不可再录音/播放，并取消写卡任务。

批量删除先由服务器预检，按空卡和已有录音分组，各自确认并独立执行。空卡提示数量；有录音组单独显示卡片数、录音数和原NFC网址失效警告。取消一组不自动执行另一组。确认至执行之间若录音/版本变化，拒绝该组并要求重新预检，不能把刚产生录音的卡按空卡删除。

采用逻辑删除保留编号历史与审计；原录音与未完成上传通过既有失效/私有对象回收机制处理。删除不回收编号或token，不在本轮提供恢复按钮，也不宣称立即物理清除。服务器每组原子处理，客户端按组展示成功或失败；访问控制不能只依赖确认弹窗。

## 6. Android 信息架构

全局菜单承载账号信息、退出登录、语言与NFC设置。未登录显示登录入口，不在登录后反复占用主要操作区。中/日/英三语覆盖业务状态、确认框和异常，默认日语，持久保存用户选择。

主要工作入口分为四个独立页面：

1. 卡片管理：选择分类、列表、搜索/筛选、查看写卡/录音状态和录音提交时间、试听。
2. 单张写卡：明确选卡并启动；已写卡只有显式“重新写卡”才处理。
3. 自动写卡：独立模式，选择一个分类、显示符合条件的待写数量、明确点击开始。普通管理页面不启用NFC写入。
4. 批量编辑：选择卡片后移动、分组删除、重置，沿用网页相同权限和确认语义。

界面使用分层标题、清楚的当前分类/编号与主要动作，不把所有按钮平铺在一个屏幕。成功、警告、失败不能只靠颜色区分。技术术语不直接作为日常命令。

## 7. 自动写卡状态机

模式只领取当前分类中启用、未录音、待写的卡片；失败项由明确重试入口处理，不自动把已写卡重新写入。进入模式或切换分类本身不启动写入。

流程：准备 → 开始 → 等待芯片 → 写入 → 重新物理读取并精确核验URL → 同步结果 → 提示移开 → 下一张。屏幕突出当前编号、完成/剩余数和当前结果。必须识别标签已移开才进入下一张，不能把同一枚仍贴着的芯片连续覆盖为多个编号；UID即使被用于本机临时去重，也不上传或成为卡片身份。

未格式化、只读、容量不足、移开中断、读回不符不能报告成功。写失败暂停当前项，提供重试、跳过和退出；跳过不标verified。断网时保留核验结果并暂停下一张，联网自动同步后仍须明确继续。未同步结果不作为服务器已完成展示。

切后台、锁屏、退出模式、会话失效均停止领取/写入。返回前台不自动恢复。管理员移动/删除/绑定当前卡时，重新检查服务器版本和资格，不依据旧列表继续写；进行中的物理动作无法回滚，须明确报告需检查的原网址，不能给新任务误报成功。多人写卡须服务端任务租约防止同任务被两台设备自动领取，退出/过期释放且上报按身份、版本与租约校验。

## 8. 登录与自动同步

设备登录一次后安全保存可续期会话，不保存明文密码；refresh token 使用Android Keystore保护的加密存储，禁用备份/日志泄漏。启动自动恢复并验证运营角色，过期串行刷新，失败或角色撤销返回登录；主动退出清除会话并立即停止NFC。不同账号的未同步报告不得混用。

列表进入/返回时自动刷新，保留易发现的手动刷新操作但不作为全局主菜单核心项。写卡结果自动同步，不再要求点击“传送待同步结果”。异常用可理解文案，如“有2张卡的结果尚未同步”，提供重试。任务已变更的结果解释原因与后果后才允许丢弃，不静默丢弃或冒充成功。

## 9. 迁移与兼容

现存标签、录音和URL不得重建。旧batch按非空规范化名称映射正式分类，空batch映射未分类；先只读输出虚构示例格式的迁移统计，由集成负责人确认真实映射及代码分配顺序，再执行迁移。已有展示编号保留作历史别名以支持搜索，新编号写入审计；新生成编号不与保留历史别名冲突。迁移前备份并验证回滚路径。

新模型、版本与租约接口先定义在API契约并测试，再更新两端。旧版Android不认识新分类/版本规则时须明确提示升级并禁止写卡，不允许以旧协议绕过任务保护。兼容访客API，录音与播放不因管理改版中断。

## 10. 验收与实施拆分

先实施共享后端和网页分类管理，再接安卓会话/导航和单张写卡，最后自动模式与批量编辑，统一回归后成套发布。每段另写可执行实施计划，不把本设计当作已实现的API说明。

验收必须包括：并发开卡与幂等；移动后旧号不复用、URL/音频不变；重置不改编号；删除分组与录音竞态；认证和RLS拒绝；稳定筛选排序；三语无遗漏；登录重启恢复/撤销/退出；同芯片未移开不推进；双写卡端租约冲突；断网、切后台、任务移动/删除时暂停与恢复；实体Android写后读回和独立手机播放。自动化测试、截图检查及真机记录分别归档。
