# 参观者可选地点设计

## 目标与范围

在现有云端录音流程增加可选地点，默认日语，保留中文。流程为：打开独立 NFC URL、查询卡片；未绑定时先选地点或跳过，再录音、试听或重录、填写可选昵称、提交。已绑定卡片直接播放，不要求重新选点。选点不改变 NFC URL、编号或录音权限。

## 方案

采用 Google Maps JavaScript API 与 Places API (New)，提供地图拖动和地名搜索。仅外链 Google Maps 无法可靠将选点结果带回；仅手填地点不满足地图选点要求，因此不作为主方案。地图加载失败、额度耗尽或搜索不可用时，保留跳过入口，不阻塞录音。

## 界面

默认中心福冈市，初始位置只是视图中心，不自动视为用户选择。用户明确确认地图上的点，或选择搜索结果后确认；可清除、返回修改或跳过。地图按需加载，已绑定卡片不为播放自动加载地图。搜索遵守 Google 署名要求；不获取设备 GPS。

## 数据与权限

以可空 location 对象扩展录音提交与查询契约。区分用户手动选点与 Google 搜索结果来源：手动选点保存用户明确选择的经纬度；搜索结果以可持久化的 place ID 为主，不默认长期存储 Google 返回的地名、地址或坐标。实现前核对当前条款，必要的动态展示按规则重新获取。用户自填地点描述独立于 Google 字段，长度受限。

服务端验证对象类型、来源、坐标范围、place ID 和描述长度；地点与录音在同一原子绑定中保存，不能绑定失败后单独留下地点。旧客户端不传 location 等价于空；旧录音仍可播放。重置和删除随录音移除地点。访客无单独修改绑定地点的权限。后台可查看地点描述及地图入口；用户内容按文本渲染，不拼接 HTML。

地点是用户主动分享的回忆地点，不是实时定位。更新现有隐私说明，明确地点可选且会随录音公开，避免用户误分享住址等敏感地点。

## 费用与配置

独立 Google 项目已启用计费及 API，浏览器密钥有来源和服务限制。先查询各 API 可调整的实际配额，设置保守请求上限并记录结果，不将预算提醒描述为硬上限，不申请付费额度提升。测试只用必要的少量真实请求。密钥不在工程文档、测试快照或日志中输出；部署使用受控配置。预算配置不能订阅额外付费服务。

## 发布与兼容

先冻结接口、增加兼容迁移和后端，再实现客户端。当前工作分支还包含未发布的管理 V2，地图发布不得顺带破坏旧 Android 写卡协议；需隔离兼容发布或按 V2 发布清单成套升级。发布前检查生产迁移差异及数据备份，不删除现有录音。

## 验证

覆盖跳过、确认、修改、地图失败、搜索失败、空地点旧数据、非法坐标、超长输入、并发绑定与重置清理。运行前端全量测试、普通及 Pages 构建、后端授权和并发测试。桌面和手机宽度截图检查。真实地图验证加载、搜索与拖动，独立浏览器验证录音地点云端读取；手机麦克风和实体 NFC 仍需真人实测，不用模拟测试替代。

## 完成定义

用量保护有查询证据，地点数据可云端保存和读取，后台可查看，地图失败不阻塞原流程，旧录音不受影响；测试通过且发布状态明确。需要真人完成的验收逐项列出。
