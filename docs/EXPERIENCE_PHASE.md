# 体验优化阶段

日期：2026-10-15。状态：用户已提出方向，具体界面设计、优先级和功能增量尚待确认。本文是下一阶段工作简报，不是已经批准的详细设计或已实施清单。

## 目标与边界

从“功能跑通”提升为参观者容易理解、运营者高效管理、工作人员现场写卡清晰可靠的体验。覆盖三个端，而非只给网页换皮。免安装/免访客账号、一卡一网址、一段有效音频、服务端权限及私有存储均不改变。默认日语、中文可切换。

## 三条工作线

### 参观者网页

候选重点：未录音/录音中/试听/上传/成功/播放各状态的层级与一致性；手机操作区域、可读性和无障碍；麦克风拒绝、上传失败和播放链接失效的恢复；福冈市回忆主题文案与公开收听告知。不能为追求简洁省去提交确认或把失败显示为成功。

验收方向：首次参与者能独立完成录音与提交，回访者能直接找到播放入口；重录不误提交、提交不重复触发，错误能恢复。用具体手机/浏览器记录结果。

### 运营管理后台

用户明确强调管理体验重要。候选重点：区分录音绑定状态与写卡状态；搜索、筛选、批次定位和试听；CSV 导入结果、错误反馈与重试；重置/停用的影响说明与确认；小屏管理的操作密度和信息层级。批量破坏性操作、统计看板等新能力不能默认为已批准范围。

验收方向：从真实任务出发检查“找到某枚展签→判断状态→试听→处理异常”，减少无效跳转；危险操作不混淆，分页/导出不漏项。优先改善既有能力，再决定是否新增功能。

### 管理人员 Android 手机应用

当前指已有 NFC 写卡端，不擅自扩展为 iOS 管理应用或新增另一套数据源。候选重点：登录、批次/任务选择、当前待写标签、准备/写入/读回/成功/失败/暂停状态；下一枚与重试操作；待同步报告、过时报告处理、断网和会话过期；单手操作与日文/中文适配。

验收方向：连续写卡时始终知道“现在是哪枚、是否真正读回通过、下一步做什么”；失败不误标 verified，切后台不自动恢复写入，不因界面优化改变物理核验规则。需要安卓实机截图和实体标签回归。

## 建议实施顺序（待确认）

1. 收集现有三端截图和实际任务，形成有证据的体验问题清单；确认优先端和最影响操作的问题。
2. 先给运营后台与 Android 工作流做方案，另行定义访客视觉方向；用页面/状态稿确认，不直接全面重写。
3. 每次只落地一条完整工作流，补齐 loading/empty/error/success 状态和相应测试。
4. 桌面/手机截图检查、授权与绑定回归、安卓构建及物理写卡回归后再发布。

## 开始设计前需确认

- 三端的首要优化顺序，特别是网页后台与安卓写卡端谁先。
- 工作人员手机端主要是写卡，还是希望加入后台管理能力；后者属于新增范围，须先定权限与接口。
- 现有最费力的具体操作，以及可提供的安卓画面/设备信息。

本轮仅同步文档，不新增 API、不改生产资源、不修改界面，也不将候选项当作实现承诺。
