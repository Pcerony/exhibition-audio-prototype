# 展览 NFC 音频应用设计

## 目标

构建一个无需安装应用的移动端展览体验：每枚 NFC 芯片打开一个专属网页，用于录制或播放一段音频；另提供运营后台，用于批量管理芯片和录音。

## 已确认的产品规则

- 参观者无需安装应用或注册账号。
- 网站支持简体中文和日语，并提供明显的语言切换；记住当前浏览器的语言选择。
- 每枚芯片写入一个稳定的 HTTPS 网址，网址以 NDEF URI 记录保存。
- 尚未绑定录音的芯片页面允许参观者录音、试听、重录，并可选填昵称后提交。
- 参观者可以在提交前重录。第一份成功提交的录音占用该芯片；之后的参观者只能收听。
- 服务端必须以原子方式保证“先提交者绑定”，即使多人同时提交，也不能覆盖或绑定出多份录音。
- 运营者可以批量导入芯片、查看芯片及录音状态、试听录音、重置芯片。重置后解除当前绑定，芯片可重新录制。
- 已购芯片型号暂不清楚。批量写入前，先用一枚实体芯片验证能否写入网址，以及手机兼容性。

## 建议架构

- 构建移动端优先的响应式网页应用，包含参观者芯片页和需要登录的运营后台。
- Supabase 提供 Postgres 数据库、私有音频对象存储、运营者身份认证，以及处理参观者请求的 Edge Functions（边缘函数）。
- 网页前端部署到支持直接访问子路径的静态网站托管服务。条件允许时，为 NFC 网址使用稳定的自有 HTTPS 域名。网页托管与 Supabase 后端彼此独立。
- 第一版原型使用 GitHub Pages 提供公开 HTTPS 预览，代码仓库和页面均为公开内容；访客网址使用兼容项目子路径的 hash 路由。
- 每个 NFC 网址包含难以猜测的随机令牌，而不是递增的数据库编号。可行时数据库只保存令牌哈希；浏览器中绝不暴露 Supabase 服务角色密钥。
- 音频保存在私有存储桶中。参观者通过后端生成的短时有效签名链接收听已绑定录音；访客请求不能替换或删除录音。
- 运营者接口要求通过 Supabase Auth 登录，并在服务端验证权限。重置操作记录时间及操作账号。

## 数据与状态

- `tags`（芯片表）：内部 ID、令牌哈希、展示编号、状态（`unbound` 未绑定或 `bound` 已绑定）、创建时间、可选批次名称。
- `recordings`（录音表）：芯片 ID、存储对象路径、可选昵称、MIME 类型、时长、创建时间，以及防滥用所需的上传会话信息。
- 每枚芯片最多只有一份有效录音。重置会删除或解除当前录音及其关联，使芯片回到 `unbound`；参观者不会再看到之前的录音。
- 批量导入会创建芯片记录和对应的随机网址。运营后台可导出 CSV，供芯片写入流程使用。实体芯片写入需单独通过试点验证。

## 参观者流程

1. 参观者碰触芯片，手机浏览器打开对应 HTTPS 网址。
2. 页面查询芯片状态。已绑定时显示音频播放器和可选昵称；令牌无效或芯片不可用时显示清楚的提示。
3. 未绑定时提供麦克风权限请求、录音控制、录音试听、可选昵称和提交操作。
4. 提交前用简短说明告知参观者：提交的声音录音将可被扫描这枚展览芯片的人播放。只有参观者主动选择录音后，网页才申请麦克风权限。
5. 提交时上传候选录音并以原子操作绑定芯片。如果另一位参观者先成功，丢弃本次未获胜的上传，并显示已绑定的录音。
6. 麦克风、网络或上传失败时，在浏览器能力允许的范围内保留本地试听内容，并提供重试；失败时不能误显示为已绑定。

## 运营流程

- 运营者登录受保护的后台。
- 可搜索或筛选的列表显示展示编号、批次、绑定状态、昵称、录音时间，以及试听和重置操作。
- CSV 导入会在创建前校验数据，并报告重复或格式错误的行。CSV 导出包含展示编号和对应网址，不包含与芯片写入无关的秘密信息。
- 重置前需要确认。操作将删除当前录音文件及关联，并让芯片重新开放录制；记录操作人和时间。
- 第一版只有一种运营者角色；暂不实现多角色权限和高级分析。

## 安全、隐私与可靠性

- 服务端限制文件类型和大小；明确支持的录音格式，并在 iPhone Safari 和 Android 浏览器中实测。
- 禁止公开网页直接修改芯片状态、存储路径或运营者数据。只有持有服务端凭证的 Edge Function 才能绑定或重置芯片。
- 绑定操作必须事务化或原子化。并发时未获胜的录音不得覆盖已绑定录音。
- 对匿名上传设置基础频率和体积限制。随机网址不应被当作允许覆盖录音的凭证。
- 在录音提交时说明录音将公开播放。除可选昵称和必要的运维信息外，尽量不收集访客身份信息。
- 所有访问使用 HTTPS。对无效、已重置、停用或删除的芯片提供安全且明确的错误页面。
- 展览结束后的保留时长、隐私说明的具体文案和上传上限，需在上线前作为运营设置确认。

## 第一版范围

包含：参观者录音、试听、可选昵称、首次绑定、音频播放；运营者登录、CSV 批量导入/导出、芯片状态列表和重置；针对手机的响应式与无障碍支持。

原型阶段另包含中日语言切换和 GitHub Pages 手机预览。为便于手机实测，原型数据仍按浏览器分别保存；它不是云端多设备版本。

暂不包含：原生手机应用、参观者账号、评论/点赞、社交分享、除运营者试听和重置之外的审核流程、多语言内容管理、离线上传队列和高级分析。

## 验收验证

- 验证试点 NFC 芯片能写入 HTTPS NDEF URI，并能在代表性的 iPhone 和 Android 手机上打开预期参观页面。
- 在当前版本的 iPhone Safari 和 Android Chrome 中测试麦克风授权、录音、试听、上传和播放。
- 测试并发提交时恰有一份有效录音，以及后来的访客无法覆盖它。
- 测试运营者权限、批量导入和重置；确认重置会移除当前录音并重新开放录制。
- 测试无效令牌、不支持的文件、大小限制、上传中断和后端/网络错误。

## 上线前待确认事项

- 用一枚试点芯片确认型号、可写 NDEF 容量及网址写入能力。
- 在 GitHub Actions 构建和发布成功后，用 HTTPS 页面在 iPhone Safari 实测麦克风授权及录音。
- 选择稳定域名和前端网站托管账号。
- 创建 Supabase 项目，并根据展览地点和隐私要求选择部署区域。
- 上线前确认芯片数量、展期、单段录音最长时长，以及展览结束后的保留/删除日期。
- 提供运营者账号邮箱。账号密码应直接在服务商后台设置，切勿发送到聊天中。
